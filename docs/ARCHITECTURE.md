# Architecture

## One core, two artifacts

`src/profiles.js` contains immutable Stable and Hardened policy objects. `scripts/build.mjs` reads a fixed, ordered list of source modules, removes their narrowly defined single-line imports and declaration exports, and wraps the result in one IIFE. It embeds one profile and a userscript metadata header. It does not evaluate source strings, download code, or minify the output.

The assembler is intentionally small and is not a general-purpose JavaScript bundler. Unsupported import/export syntax fails the build. Generated scripts are syntax-checked before writing. The output contains no timestamps or absolute machine paths, so the same source produces identical UTF-8 files. `dist/SHA256SUMS` covers both scripts. `npm run build:check` compares generated bytes against tracked files.

## Realm installation

`installPrivacyCore` installs each module independently. A non-configurable symbol marker prevents double installation within a document. Status and module results are frozen after setup. This marker is visible to the page and is not a security boundary.

Each realm captures its own native methods before replacing them. The patcher preserves property flags and uses function proxies to keep function names, lengths, and native receiver checks where possible. It maps patched `Function.prototype.toString` results back to the captured originals. This is a compatibility measure: a clean realm or other reflection mechanisms can still detect patches.

Frames receive full installation through three paths: synchronous `contentWindow`/`contentDocument` access, a document mutation observer that scans inserted descendants, and captured iframe load events. Each accessible frame is guarded independently. There is no cross-origin access bypass, worker injection, global DOM insertion hook, or guarantee that inline frame code executes after installation.

## Seed and pixels

A 128-bit random storage value is mixed with the exact origin and reduced to a 32-bit deterministic masking seed. This is noise selection, not a cryptographic secret. The storage entry is page-readable and mutable. Reloads in the same origin/tab reuse the stored value. Denied storage uses per-document randomness without deriving a fallback from the user agent or hardware.

Pixel selection depends on the seed, surface dimensions, and absolute pixel coordinates. A selected pixel's RGB least significant bits are set to deterministic values. Repeated application is idempotent and changes each RGB byte by at most one. Fully opaque pixels only are eligible; alpha is never modified. Selection density is approximately one in 3,072 pixels for Stable and one in 128 for Hardened. Some selected pixels already have the target bits, so the number of actual changes is smaller and can be zero.

Exports draw onto a temporary canvas and read pixels through captured native methods. The source is never written or assigned a context type by the export hook. Hardened also patches 2D readback, with cropping mapped back to absolute coordinates. Coordinate conversion is recorded during the native call, so custom conversions occur once and native range checks remain intact. Native taint, invalid receiver, zero-size, and callback validation errors remain native. Color conversion, lossy codecs, unsupported pixel formats, and canvas allocation failures limit consistency; see the threat model.

## Network and media policy

Stable leaves WebRTC untouched. Hardened wraps the native peer connection constructor and `setConfiguration`, overriding the native ICE policy with `relay`. Dictionary reads preserve inherited members and getter receivers. Browser ICE handling, event listeners, descriptions, and statistics remain native; the script does not rewrite SDP or synthesize ICE events. A site without working TURN relay candidates cannot establish the usual peer connection under this policy.

The offline audio module is Hardened-only. It processes each returned `AudioBuffer` at most once and installs a capture listener at context construction so the completion event and rendering promise see the same modified buffer. Sparse nonzero samples receive a deterministic perturbation of `1e-7`. It leaves silence and real-time audio APIs intact. Existing offline contexts created before installation have weaker event-path coverage.

## Native data models

The project leaves permissions, plugin arrays, MIME arrays, and automation state native. It does not create pretend `PermissionStatus`, `BatteryManager`, or `MediaDeviceInfo` objects. Hardened disables an existing battery method, filters unlabeled devices while retaining native device objects, and removes high-entropy Client Hints result keys. Hardware values are capped rather than randomized into unsupported device profiles.
